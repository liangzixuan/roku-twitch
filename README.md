# Roku Twitch 个人 MVP

这份代码包含 Roku 客户端和电脑/NAS 服务，供同一家庭网络内的一台 Roku 使用。它支持关注列表与收藏置顶、主播搜索、验证码登录、频道订阅查询、直播和 VOD 播放，以及观看进度、指定时间跳转、清晰度选择和有限次数的断线恢复。

## 现在能做什么

登录功能已实现，但需要先配置 Twitch 应用的 Client ID，再安装到 Roku。没有默认账号，也没有预填的 Twitch 凭据。

账号登录与视频播放使用两份不同的凭据：

- Roku 的验证码登录用于确认账号、查询频道订阅和关注列表，请求 `user:read:subscriptions` 与 `user:read:follows` 权限。
- Streamlink 的播放身份来自同一账号的 Twitch 网页登录。服务会检查两处账号是否一致。

Twitch 的应用授权令牌不能直接替代 Streamlink 所需的网页登录令牌。详见 [Streamlink 认证说明](https://streamlink.github.io/cli/plugins/twitch.html#authentication)。

已订阅频道不代表此播放器一定没有广告。主播需要启用订阅免广告，播放服务也需要正确识别账号。本项目尚未确认订阅免广告效果。主播自行播放的赞助内容仍会出现。详见 [Twitch 免广告说明](https://help.twitch.tv/s/article/twitch-turbo-guide?language=en_US)。

## 获取源码

```sh
git clone https://github.com/liangzixuan/roku-twitch.git
cd roku-twitch
```

也可在 GitHub 选择 **Code → Download ZIP**，解压后进入项目文件夹。仓库不包含账号凭据、配对配置或已配置的 Roku 安装包。

## 安装电脑服务

需要 Python 3.11 或更高版本、FFmpeg，以及能与 Roku 通信的电脑或 NAS。在本项目目录执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

macOS 可用 Homebrew 安装 FFmpeg：

```sh
brew install ffmpeg
```

Linux/NAS 使用系统提供的 FFmpeg 安装方式。先执行 `ffmpeg -version` 确认安装成功。

## 迁移到 Windows 11

Windows 迁移步骤见 [WINDOWS.md](WINDOWS.md)。运行包包含安装依赖、配置地址和启动服务的三个 `.cmd` 脚本。使用 Python 3.14 与 FFmpeg，不需要 Docker。账号和记录在停止旧服务后单独复制；运行包不包含私人数据。Windows 安装和播放仍需在目标电脑验证。

## 首次配置

1. 在 [Twitch 开发者控制台](https://dev.twitch.tv/console/apps) 注册应用。
2. 将 Client Type 设为 **Public**。如果注册页要求 OAuth Redirect URL，可以填写 `http://localhost:3000`；本项目使用设备验证码流程。
3. 复制应用的 **Client ID**。不需要 Client Secret。
4. 在项目目录执行配置工具：

```sh
.venv/bin/python -m server.setup
```

工具会询问 Client ID 和电脑/NAS 的局域网地址，例如 `http://192.168.1.20:58787`。这里不能填 `localhost`，因为 Roku 会把它理解为自身。建议在路由器上为服务器保留固定地址。

工具会保存本地配置，并生成 `dist/roku-twitch.zip`。该安装包含有本地服务的配对密钥，请勿公开分享。

启动服务：

```sh
.venv/bin/python -m server.run
```

启动工具会读取 Roku 配置中的端口，保证服务和安装包使用同一个端口。保持该窗口运行。仅运行一个服务进程，不要添加 `--workers` 或 `--reload`。电脑休眠或关闭服务后，Roku 无法播放。

此 MVP 默认通过 HTTP 在可信家庭网络内通信。不要配置公网端口转发。使用共享或不可信网络时，需要先配置 HTTPS。账号凭据以本地文件保存。macOS/Linux 使用限制性文件权限；Windows 应放在当前用户的个人目录并检查目录访问权限。文件内容没有加密。

## 安装 Roku 客户端并登录

1. 按 [Roku 开发者模式说明](https://developer.roku.com/dev/docs/developer-setup) 开启开发者模式。
2. 在电脑浏览器中打开 Roku 的设备地址，进入开发者安装页面。
3. 上传 `dist/roku-twitch.zip`。Roku 的开发者安装槽只能保留一个侧载应用，安装会替换当前侧载应用。
4. 在电视上选择 **Sign in to Twitch**。
5. 在手机打开电视显示的 Twitch 激活地址，输入验证码，并用已订阅频道的账号授权。
6. 登录完成后进入 **Following** 首页。按遥控器 `*` 打开设置，可选择 **Check account** 查看账号状态。

Roku 界面暂用英文，避免依赖设备上的中文字体。

## 关注列表首页

0.6.0 的首页左侧显示当前账号关注的主播，每行包含头像、名称、`LIVE` 或 `OFFLINE`，直播中的频道还显示观众数。选中主播后，右侧显示直播标题、游戏或分类名称及操作提示。头像未加载或加载失败时显示名称首字。置顶频道排在其他频道前面。每组内在线频道优先，按观众数从高到低排序；相同观众数和离线频道按名称排序。

- 选择在线主播，打开直播。
- 选择离线主播，打开该主播的 VOD 列表。
- 选中时会重新检查在线状态。主播刚下线时会转到 VOD 列表。
- 首页的 **Show: All followed** / **Show: Live only** 可用 OK 切换全部关注与只看在线。没有主播在线时仍可切回全部关注，查看离线主播的 VOD。
- 首页每 60 秒在后台刷新。播放、打开菜单、浏览录像或其他请求进行时会跳过自动刷新。读取全部分页后再显示结果，避免只显示前 100 个关注频道。
- 刷新会保留当前选中的主播或功能行。若主播取消关注，或在只看在线模式下离线，则选择附近的有效行。刷新失败保留原列表；头像查询失败也不阻止显示频道。
- 列表底部的 **Refresh** 可手动更新，退出直播后也会刷新。后台刷新期间仍可选择频道。
- 在主播行按遥控器 `*` 打开主播菜单，可选择 **Watch live**、**Past broadcasts**、**Pin to top** / **Unpin** 或 **Settings**。主播在线时也可以查看历史录像。
- 在其他行按 `*` 打开设置，保留手动输入频道、订阅查询、登录和退出选项。按返回键回到关注列表。

旧版登录缺少关注权限时，首页会显示 **Enable Following**。选择后，在手机的 Twitch 激活页输入电视验证码，用同一个账号同意新增权限。现有播放凭据会保留，无需重新导入。取消授权、授权失败或选择不同账号时，本地原有登录会保留。

关注列表依据 [Twitch Get Followed Channels](https://dev.twitch.tv/docs/api/reference/#get-followed-channels)，在线状态与观众数依据 [Get Streams](https://dev.twitch.tv/docs/api/reference/#get-streams)。列表按最近一次刷新得到的观众数排序。头像通过 [Get Users](https://dev.twitch.tv/docs/api/reference/#get-users) 获取，电脑服务缓存一小时；直播信息每轮重新读取。无需新增 Twitch 授权。

## 收藏置顶

选中首页的主播，按遥控器 `*`，选择 **Pin to top**。该主播会移到频道列表顶部，并显示 `PINNED`。再次打开菜单选择 **Unpin** 可取消置顶。保存成功后列表立即重排，焦点仍停在同一个主播上；保存失败会显示错误，保留原来的排序。

置顶频道排在其他频道前面，包括离线频道。每组内在线频道优先，按观众数从高到低排序，观众数相同或离线时按名称排序。**Live only** 仍会隐藏离线频道。继续观看和筛选入口的位置不变。

置顶保存在电脑的 `data/favorites.json`，按 Twitch 账号和主播 ID 区分。重启服务、重新安装客户端或主播改名不会丢失置顶。它不修改 Twitch 的关注关系，也不需要新增授权。取消关注后主播不再显示；重新关注同一主播时仍保留置顶。

## 继续观看

0.5.0 的首页增加 **Continue watching**。它显示当前账号最近观看但尚未看完的录像，按最后保存时间排序，最多保留 100 条。

从频道列表或继续观看列表打开已看过的 VOD 时，界面提供 **Resume at ...**、**Start from beginning** 和 **Cancel**。选择继续观看时，会重新获取有效的播放地址，再从保存位置开始。

Roku 每 15 秒向电脑服务保存一次实际播放位置，正常返回退出时再保存一次。尚未确认的快进预览不会覆盖进度。直接按 Roku Home、断电或网络中断时，最近一次保存之后的进度可能丢失。恢复播放的位置可能略早于保存位置，取决于视频分片。

进度保存在电脑的 `data/history.json`，按 Twitch 账号区分，不保存播放地址或令牌。重启服务、重新安装 Roku 客户端或重新登录后仍可读取。播放自然结束或进入最后 10 秒后，该录像从继续观看列表移除。旧版本没有保存过的观看进度无法恢复。已删除或权限发生变化的录像仍可能出现在本地列表中，打开时会重新验证可用性。

进度条可见时，按返回键立即隐藏它，视频继续保持原来的播放或暂停状态。进度条隐藏后，再按返回键退出 VOD。长按快进、快退期间按返回键，会取消尚未确认的跳转并隐藏进度条。松开方向键后，跳转已经确认，此时返回键只隐藏进度条。按上、下键可再次显示。

## VOD 列表中的观看进度

0.9.0 的 VOD 列表将标题与日期、时长分成两行。看过但尚未完成的录像显示 `Watched` 和已观看时间，下方有细进度条。退出播放后，列表会更新进度并保留选中的录像。继续观看列表也使用相同的行样式。

进度来自当前账号的本地观看记录。未保存过进度的录像不显示进度条。已看完、标记为已看完或手动移除的记录会清除进度，因此不会显示永久的“已看完”标签。

## 指定时间、录像详情和断线恢复

### 跳到指定时间

播放 VOD 时按遥控器 `*`，选择 **Jump to time**。输入 `1:23:45`、`83:45` 或 `5025`，再选 **Jump**。这三个输入都表示第 5025 秒。输入必须早于视频结束时间；格式或范围错误时，对话框会提示并保留输入。

跳转保留原来的播放或暂停状态。跳转位置受 HLS 分片边界影响，可能略有偏差。进度条短暂显示，按返回键可立即隐藏。**Cancel** 或对话框中的返回操作不改变播放位置。

### VOD 封面和完整标题

VOD 与继续观看列表的左侧保留录像和观看进度，右侧显示封面、日期、时长及完整标题。按右键进入标题区，用上下键阅读长标题；按左键或返回键回到列表。再次按返回键离开列表。

封面直接读取 Twitch 的公开图片地址，不携带本地配对密钥。图片加载失败时显示 **No preview**，仍可选择录像播放。旧观看记录可能没有封面和日期；重新播放并保存进度后会补齐。

### 断线恢复

播放出错、电脑会话中断，或未暂停的视频连续缓冲 30 秒时，客户端会尝试重新连接。最多尝试 3 次，发出请求前分别等待 2、5、10 秒。每次获取新播放地址或重建直播流，使用已保存的清晰度偏好。VOD 使用最近确认的播放位置；若启动后还未确认位置，则保留原来的续播起点。暂停意图也会保留。

重连时显示 **Reconnecting**，按返回键可取消。暂停、长按快进预览、正常结束和主动退出不会触发缓冲超时恢复。连续正常播放 60 秒后，才重置重试次数。

账号失效、播放凭据失效或不匹配、录像查询确认不可用、主播已下线时停止重试并显示错误。其他无法明确分类的播放错误仍受 3 次上限限制。重连不会自动重新登录，也不会删除观看记录。

恢复请求绑定当前账号和播放会话。重复请求不会重复启动同一轮恢复，旧会话不能覆盖新选择，取消操作也能停止响应尚未到达电视的新播放任务。电脑服务重启后，内存中的恢复会话会失效，需要重新选择录像或频道。

自动测试覆盖时间输入、暂停状态、恢复位置、重试上限、旧请求、取消恢复、封面回退及标题区按键。设备上的播放和遥控器行为仍需真机验证。

## 搜索主播

首页选择 **Search channels**，输入频道名后选择 **Search**。搜索结果显示主播名称、登录名及在线状态。选择结果时会重新检查状态：在线则播放直播，离线则打开 VOD 列表。搜索结果支持翻页，**New search** 可重新输入；从录像列表返回时会回到原搜索结果。

搜索不要求先关注主播，也不修改关注关系。它使用 [Twitch Search Channels 接口](https://dev.twitch.tv/docs/api/reference/#search-channels)，该接口返回近六个月内有直播记录的匹配频道。找不到时仍可在设置中输入完整频道登录名。

## 选择视频清晰度

播放直播时按遥控器 `*` 打开清晰度菜单。播放 VOD 时按 `*`，再选择 **Video quality**。菜单显示 **Highest available** 和当前视频实际提供的 H.264 视频档位，例如 **1080p60**、**720p60**。只读取清晰度列表不会停止当前播放。菜单打开时，返回键只关闭菜单。

选择档位后会短暂缓冲。VOD 从确认过的当前位置继续，暂停中的 VOD 仍保持暂停。直播切换会重新连接当前直播。列表读取失败可关闭后重试；无效档位或旧播放会话的切换请求会被拒绝。直播和 VOD 都可用 OK 或播放键暂停、继续。

偏好保存在电脑的 `data/quality.json`，按 Twitch 账号区分。之后打开视频时会使用该档位；视频没有该档位时使用最高可用画质，并保留原偏好。**Highest available** 表示固定选择最高可用画质，不是按网络速度自动降档。

清晰度来自 [Streamlink 的 JSON 输出](https://streamlink.github.io/cli.html#cmdoption-json)。VOD 使用对应档位的视频播放列表；直播继续使用现有的 Streamlink 与 FFmpeg 播放流程。

## 管理继续观看

0.7.0 在 **Continue watching** 列表加入录像管理。选中录像后按 `*`：

- **Remove from continue watching**：移除该记录并清除续播进度。
- **Mark as watched**：按已看完处理，移除该记录并清除续播进度，与自然播放结束时的结果相同。
- **Cancel**：保留记录。

移除后再次从频道 VOD 列表打开该录像，会从头播放。再次观看会创建新的进度记录。这些操作只修改当前 Twitch 账号的本地记录，不会删除 Twitch 上的录像或修改其他账号的记录。

打开继续观看中的录像时，如果 Twitch 明确返回录像不可用，会显示 **Remove from continue watching** 和 **Keep**。网络故障、凭据过期或播放地址解析失败不会自动删除记录，也不会被当作已删除的录像。

正在播放的同一录像不能清理，避免下一次进度保存又将它加回列表。其他记录的清理不停止当前播放。列表更新失败时保留原列表，允许重试。

0.7.0 的电脑服务已按要求更新并启动。登录、播放凭据和观看记录已保留；记录读取、管理接口校验和配对保护检查通过。无需重新登录或授权。

## 配置播放身份

验证码登录成功后，仍需要导入一次网页播放凭据。该凭据可以访问你的 Twitch 账号，请只在自己的电脑/NAS 上输入，不要发到聊天或工单中。

1. 在电脑浏览器中登录同一个 Twitch 账号。
2. 按 [Streamlink 官方认证说明](https://streamlink.github.io/cli/plugins/twitch.html#authentication) 取得该账号的网页登录令牌。
3. 在电脑/NAS 的项目目录执行：

```sh
.venv/bin/python -m server.setup import-playback
```

4. 在隐藏输入提示中粘贴令牌。工具只将凭据发到 Twitch 验证接口，验证后保存在本机 `data/playback.json`。
5. 回到 Roku，选择 **Check account**。两处登录为同一账号时，会显示 `Playback identity verified`。

网页凭据不会自动刷新。如果凭据失效，需要重新导入。更换播放凭据前先停止播放。

## 验证订阅和播放

1. 按遥控器 `*` 打开设置，选择 **Choose channel**，输入已订阅频道的登录名，不要输入完整网址。
2. 选择 **Check channel subscription**，确认显示已订阅。
3. 在频道直播时，选择 **Play live channel**。
4. 检查电视上的声音、画面和连续播放情况。
5. 检查进入频道和后续播放时是否出现广告或停顿。一次没看到广告不能证明所有广告时段都能免广告。

按返回键停止播放。选择 **Sign out / cancel login** 会停止视频并删除本地账号和播放凭据。服务会尝试撤销本应用的访问令牌；网络不可用时仍会删除本地凭据。此操作不会注销 Twitch 网页账号。若要撤销网页登录令牌，请使用 Twitch 的 **Sign Out Everywhere**。

## 播放离线频道的 VOD

1. 上传配置工具生成的 `dist/roku-twitch.zip` 到 Roku 开发者安装页面，不需要解压。
2. 按遥控器 `*` 打开设置，确认版本为 **0.10.0**，服务器地址端口为 **58787**。
3. 选择 **Choose channel**，输入频道登录名。
4. 选择 **Browse VODs**。每行显示录像日期、时长和标题，按发布时间从新到旧排列。
5. 选择一条录像开始播放。使用 OK 或播放键暂停、继续；短按左右键跳 10 秒，长按逐步加速。松开后跳到屏幕显示的时间。调整时按返回键取消并隐藏进度条，再按返回键回到录像列表。
6. 列表每页最多 20 条。滚动到底部可选择 **Next page**、**Previous page** 或 **Back**。

升级保留电脑上的账号和播放凭据。频道不需要正在直播，但必须有已保存且账号可访问的录像。没有录像时会显示空列表提示；已删除或受限的录像可能无法播放。

VOD 使用 Streamlink 获取完整 HLS 播放地址，再由 Roku 直接读取 Twitch 的视频服务。这样无需先下载整段录像。电脑服务仍需运行，Roku 每 15 秒确认一次播放会话，暂停时也会继续确认。每次重新选择录像都会获取新地址；有保存进度时可选择继续观看或从头播放。

列表依据 [Twitch Get Videos 接口](https://dev.twitch.tv/docs/api/videos/)，播放器使用 [Roku Video 节点](https://developer.roku.com/dev/docs/video)。

## 清晰度、进度控制和图标

未设置清晰度偏好时，直播和 VOD 使用 Streamlink 的 `best`，选择可取得的最高 H.264 清晰度。视频不做画质提升，也不自动切换到较低清晰度。

VOD 短按左右键跳 10 秒。按住时每 0.4 秒更新一次目标位置；持续约 2 秒、5 秒、10 秒后，每步分别跳 30 秒、60 秒、300 秒。画面下方显示目标时间和进度条，松开后执行一次跳转，避免拖动时反复缓冲。暂停时调整进度仍保持暂停。返回键可取消尚未确认的跳转。快进、快退键也支持相同操作，重播键后退 10 秒。

0.3.1 使用独立的按键区域处理 VOD 控制，并在视频状态改变时恢复焦点。长按只在应用真正失去焦点时取消。播放键的重复按下和松开事件会被应用处理，暂停意图在缓冲结束后仍保留。进度条只显示时间、播放／暂停图标，不显示操作说明；直播可用 OK 或播放键暂停和继续。按上、下键可显示 VOD 进度条。

首页图标使用 [Twitch Press Center](https://www.twitch.tv/p/press-center/) 的 Glitch 素材，提供 Roku 的 HD、FHD 和 SD 尺寸。应用名称仍为 Personal Twitch。

## 播放限制

直播使用 Streamlink 获取 H.264 视频，再由 FFmpeg 重新封装为 Roku 可读的 HLS 分片，不做视频转码。VOD 使用完整 HLS 播放列表。暂不支持聊天、下载录像、多设备并发或后台常驻安装。

频道离线时无法播放直播，可以改选 VOD。凭据失效或 Twitch 要求额外的浏览器校验时，直播和 VOD 都可能失败。部分校验需要服务器安装 Chromium，见 [Streamlink 的浏览器校验说明](https://streamlink.github.io/cli/plugins/twitch.html#client-integrity-token)。MVP 不会自动安装浏览器。

Streamlink 会在过滤嵌入广告时暂停输出。这种停顿不代表账号订阅已生效。该 MVP 没有把停顿包装成免广告，也没有修改播放器类型或使用替代账号来获取视频。

## 本地检查

验证范围包含 144 项后端测试和 272 项客户端断言。测试使用模拟 Twitch 响应和本地合成视频，不使用真实账号数据。Windows 启动脚本和实际播放需要在 Windows 电脑上验证。

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
npm ci
npm run check:roku
npm run test:roku
```

后端测试使用模拟 Twitch 响应验证登录、轮询、过期、刷新、账号匹配、访问限制和退出清理。VOD 测试覆盖离线频道列表、翻页、删除的录像、播放地址解析、超时清理和会话保活。观看进度测试覆盖保存、恢复、从头播放、账号隔离、会话失效、播放完成及退出前保存。另有一项测试用本地合成视频验证 FFmpeg 输出 H.264 HLS；这些自动测试不连接 Twitch。Roku 编译检查不能替代真机播放测试。

如果当前网络无法验证 npm 注册表的证书，可在安装编译工具时使用 Yarn 的公共注册表：`npm ci --registry=https://registry.yarnpkg.com`。不要关闭证书校验。
